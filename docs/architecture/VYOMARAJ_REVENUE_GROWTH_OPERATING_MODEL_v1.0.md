# Vyomaraj Revenue Growth, Sales & Marketing Operating Model v1.0

## Decision

Sales, marketing, growth and partnerships are added as a capability layer under the existing ShriYantra/Harness/provider-neutral architecture. The architecture is not replaced or reordered.

The ₹5–10 crore annual ambition is treated as a strategic target range, not a forecast or guarantee.

## Operating model

DISCOVER → RESEARCH → SEGMENT → POSITION → OFFER → TEST → DISTRIBUTE → ATTRACT → QUALIFY → CONVERT → DELIVER → RETAIN → RECONCILE → LEARN → SCALE.

Vyomaraj/Bharath remains the stable strategic identity. Jarvis/Laxman remains the dynamic operational executor. Kuber remains financial controller and reconciliation authority.

## Sales capabilities

- market and customer research
- ICP and segmentation
- lead discovery and qualification
- offer and pricing design
- proposals and outreach
- partnership/sponsorship/affiliate discovery
- negotiation support
- follow-up and pipeline management
- conversion and retention analysis
- upsell/cross-sell analysis
- ROI and unit economics

## Marketing capabilities

Marketing is treated as measurable experimentation rather than vanity-metric accumulation.

Every experiment records:

audience × problem × offer × platform × format × hook × CTA → traffic → qualified lead → conversion → net revenue.

Winners are scaled only when the evidence shows repeatable value and acceptable rights, policy, security and economics.

## Revenue portfolio

The engine can evaluate content, audio, books/literature, partnerships, knowledge products, digital products, services and enterprise opportunities.

No single platform, AI provider, customer or distributor is allowed to become a dependency root.

## Tool and technology strategy

Tools are replaceable capabilities beneath Harness.

- APIs for deterministic platform integration.
- MCP for approved agent-to-tool/resource connections.
- A2A for allowlisted agent-to-agent collaboration.
- First-party analytics wherever available.
- CRM/marketing/commerce adapters only through owner-approved scopes.
- Server-side secrets only.
- No credentials in browser code or prompts.
- Activation remains evidence-gated.

## Revenue truth

Views, streams, followers, clicks and forecasts are not cash.

The financial chain is:

METRIC → ATTRIBUTION → REPORTED EARNINGS → FEES/ADJUSTMENTS → SETTLEMENT → PAYMENT EVIDENCE → KUBER RECONCILIATION.

A platform must never be marked ENABLED merely because an adapter is configured.

## Current external API findings

YouTube provides Analytics and Reporting APIs for authorized channel/content-owner analytics, including monetary reporting scopes; Content ID access is restricted to eligible content partners. This makes YouTube a strong first analytics/integration candidate, subject to account authorization. 

Spotify's Web API is primarily a metadata/user-interaction API and requires authorization for user data. Spotify changed developer-access rules in 2026, so any Spotify adapter must check the current app mode and approved use case before activation.

Apple Music API supports catalog and authorized user-library integration; it should therefore be treated as a distribution/metadata adapter rather than assuming that it provides royalty settlement data.

TikTok's current Content Posting API supports direct posting/upload flows but requires app registration, approved scopes and user authorization; unaudited clients have publication restrictions. It therefore fits the existing CONFIGURED → AUTHORIZED → TESTED → ENABLED gate.

These findings do not activate any external account. They only define the provider-neutral integration requirements.
