# VYOMARAJ / JARVIS — AUTOMATED CONTENT ALIGNMENT & CLEANING

## Permanent capability

Vyomaraj/Bharath and Jarvis/Laxman must periodically inspect and maintain:

**Category → Agent → Sub-Agent → Topic → Content → Product/Media → Process → Revenue → Kuber → Owner**

### Cadence

- Continuous: validate new/changed records.
- Weekly: complete alignment scan and exception report.
- Monthly: deep historical/provenance/duplicate/revenue alignment.
- Quarterly: archive, recovery and DR integrity audit.

### Maintenance sequence

DISCOVER → SNAPSHOT → NORMALIZE → DUPLICATE DETECTION → PROVENANCE RECOVERY → TOPIC ALIGNMENT → CONTENT ALIGNMENT → PRODUCT/MEDIA ALIGNMENT → PROCESS ALIGNMENT → REVENUE ALIGNMENT → KUBER RECONCILIATION → CHANGE PLAN → OWNER AUTHENTICATION → OWNER APPROVAL → SAFE MERGE → PEER SYNC → DR REPLICATION → VERIFY → AUDIT.

### Duplicate policy

**Exact duplicate:** may be merged after owner authentication when the canonical fingerprint, source/provenance and non-conflicting metadata establish identity.

A merge must preserve:
- original IDs;
- source references;
- versions/dates;
- published references;
- process links;
- revenue attribution;
- Kuber financial events;
- audit hashes;
- rollback information.

The retired record becomes a tombstone/alias. **No silent deletion.**

**Possible duplicate:** proposal only. Similar titles are not enough when edition, language, source, date, rights or content differ.

**Conflict:** stop and escalate.

OWNER VOICE → WISPR FLOW → INTENT PARSER → OWNER AUTHENTICATION → VYOMARAJ/JARVIS → MAINTENANCE AGENT → PROPOSE → OWNER APPROVAL → APPLY → VERIFY → KUBER → DR.

### Owner protection

No maintenance agent can create an owner, self-elevate, erase audit evidence, silently delete historical content, bypass owner approval or rewrite immutable historical snapshots.

### Financial control

Every maintained record retains:

CONTENT-ID → AGENT-ID → SUB-AGENT-ID → TOPIC-ID → PRODUCT/MEDIA-ID → PROCESS-ID → PLATFORM-ID → REVENUE EVENT → KUBER LEDGER → OWNER.

Kuber is Financial Controller for both Vyomaraj/Bharath and Jarvis/Laxman.

### Important status rule

A scheduled scan proves **scan execution**, not successful cleanup.

Cleanup is VERIFIED only after changes, tests, peer synchronization, DR replication, read-after-write and audit evidence are all present.
