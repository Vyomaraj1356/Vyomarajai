3. THE 2026-10-06 REGRESSION, ITS CAUSE AND THE FIX ON THIS BRANCH
What happened. Commits 4935ec8d ("fix: rebuild transfer package d9f2b0ae after index
restore") and f735f92 ("Publish: Vyomaraj sovereign restore — original one-month design
live") restored the transfer archive and TRANSFER_MANIFEST_2026_10_04.json from an older tree
while the five member sources on disk stayed current. The result was a package that no longer
matched its own sources.

Measured, not guessed. `python3 ops/vyomaraj-core/handover/build_transfer_package.py --check`
reported exactly five members differing from source, and the unit tests reported the same
five through two failures:
    DR_SYNC_RESULTS_2026_10_04.md   15372 bytes in the archive vs 15129 on disk
    preview_reports.py              15195 vs 13055
    BUILD_AND_CONFIGURATION_2026_10_04.md  11056 vs 11042
    DEPLOYED_MATCH_2026_10_04.json  26309 vs 25330
    studio_server.py                19292 vs 18013
Why it mattered beyond a red check. The offline-tests job is the gate that verify-or-sync
`needs:`. When it failed, replication never ran — and it failed silently as far as the DR
record was concerned, because a run that never starts writes no annotation. The secondary
therefore still holds the PR #25 snapshot (0671fc59, tree 88f681aa) and has not received
4935ec8d or f735f92. That is a real Git-snapshot replication gap, stated here as a gap and not
as a mismatch: no mismatch was observed either.

The fix on this branch. The archive and its manifest were rebuilt from the current sources with
their own builder. The strongest evidence that the defect was an artifact restore and not a
content problem: rebuilt that way, the archive came out at 133,941 bytes, sha256
8125959942d3d293f4971d3f52f46a9047868a3b5f113ee6d2b80efee2240a67 — byte-for-byte the value
that PR #25's own PREVIEW_VERIFICATION_2026_10_04.json had recorded for the verified package.
No source file was edited to make a test pass; the stale artifact was regenerated. The package
has since been rebuilt again because this session also changed documents it carries (the DR
report). Its current size and SHA256 are quoted in exactly one place,
TRANSFER_MANIFEST_2026_10_04.json, and are deliberately not restated from memory here.

Second defect found and fixed on this branch. The sync workflow pinned a single, long-expired
session branch: `push.branches: [main, arena/01a10140-vyomarajai]` and the read-only PAT
diagnostic job's condition `github.ref == 'refs/heads/arena/01a10140-vyomarajai'`. No live
session has that name any more, so the diagnostic job was skipped in every run, including the
successful ones (it is recorded as `skipped` in the check-run lists above). The workflow now
triggers on `main` and `arena/**`, and the diagnostic condition is
`startsWith(github.ref, 'refs/heads/arena/')`, so the offline gate and the read-only PAT
diagnostic run on whichever branch a session actually pushes. Replication itself stays
main-only: the verify-or-sync job still requires `refs/heads/main`.
