## 1. Scope and evidence rules

This is a source-backed inventory of the current checkout and selected files inspected at reconciled commit `7b7dd403c79266d3250e6b334a7598a5432adc17`. It is not proof of live devices, connected accounts, paid subscriptions, running agents, production deployments, all private chats, or all 421 product titles. Historical archives have not been exhaustively audited for every embedded content item.

- **Registry:** the restored V16.7.24/build 194 registry, snapshot 1 October 2026. Category arithmetic is verified, not runtime status.
- **LOCAL:** a file exists in this checkout; this alone does not prove the feature works.
- **REMOTE-ONLY:** found at the pinned reconciled commit, not imported as runnable code here.
- **HISTORICAL / CLAIMED:** labels in old HTML, diagrams or configuration; not confirmed integrations or canonical child mappings.
- **UNKNOWN:** a name, value, owner, status or relationship is not established.
- **UNMAPPED:** an exact slot, parent-child assignment or product association is not supplied.
- **UNVERIFIED:** functionality has not been demonstrated by this audit.

Private contacts, account identifiers, credentials, device identifiers, populated environment values, revenue amounts and internal endpoint values are deliberately excluded. Configuration key names and public technology names are included. No controller, failover, publishing action or provider request was executed.

“Unattended” is covered in both senses: **automation intended to run without an operator** and **unresolved work requiring attention**.

### 7.3 Actual controller limitations from static inspection

- `heartbeat` makes a curl request when invoked. It does not implement a persistent 24×7 scheduler; a command name and interval variable are not a running service.
- The curl check lacks HTTP-status failure handling (`-f`), so a completed HTTP error response may still be labeled successful.
- `status` can print the device registry. Treat raw status/log output as sensitive; do not publish it.
- Device shifting logs steps, sleeps and changes local state text. It is **not proof of session transfer, remote device control or cloud migration**.
- Its “test” output is not a comprehensive assertion-based integration suite.
- Legacy environment key names such as `JARVIS_STATE_FILE`, `JARVIS_LOCK_FILE` and `JARVIS_HEARTBEAT_INTERVAL` do not consistently match the controller's `STATE_FILE`, `LOCK_FILE`, `HEARTBEAT_INTERVAL` variables. Configuration wiring needs review.
- Sourcing a shell `.env` executes its contents; treat it as trusted code, not inert JSON. Tracked personal/contact data needs separate cleanup review.
